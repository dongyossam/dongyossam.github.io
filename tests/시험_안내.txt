동요샘 노래상자 — 올리기 전 시험
================================

고칠 때마다 아래 규칙으로 시험하고, 통과해야만 올려요.

1. 단순 수정 (글귀, 색, 여백, 그림 교체)
   python3 tests/code_check.py        ← 1단계 코드 검사만

2. 기능 수정 (새 기능, 화면 배치 변경, 서버·저장 방식 수정)
   python3 tests/full_test.py         ← 1단계 코드 검사 + 2단계 전체 시험

3. 어느 쪽인지 애매하면 전체 시험을 해요.
4. 하나라도 '걸림'이 나오면 올리지 않고 먼저 고쳐요.
5. 올린 뒤에는 어떤 시험을 돌렸고 결과가 어땠는지 한 줄로 알려 드려요.


[1단계] 코드 검사가 보는 것
  - 문법 오류: index.html·시안(preview) 안의 스크립트, Collector.gs, sw.js
               national.json·manifest.webmanifest 가 제대로 읽히는지
  - 짝 맞추기: 스타일의 중괄호, 화면 뼈대 태그(div·section·nav 등)
  - 단추 → 함수: 화면이 서버에 부탁하는 기능이 서버(Collector.gs)에 다 있는지,
                 서버 기능 목록의 함수가 실제로 있는지,
                 단추에 붙은 표시(data-○○)를 처리하는 코드가 있는지
  - 판 번호: 아래 네 곳의 숫자가 같은지
      Collector.gs 맨 위 SERVER_VERSION
      index.html 의 APP.version
      sw.js 의 캐시 이름 (dongyo-shell-숫자)
      설치안내.txt 의 '지금 판'
    서버를 고쳐 새로 배포해야 하는 판이면 네 곳의 숫자를 함께 올려요.

[2단계] 전체 시험이 밟아 보는 것 (진짜 화면을 브라우저로 띄워서)
  - 손님: 첫 화면, 맨 위 메뉴 모두, 곡 열기, 노래방 화면, 곡 QR
  - 가입: 구글 로그인 → 가입 신청(동요샘 회원 신청 포함) → 계정 시트 기록
  - 승인 뒤 로그인 유지, 반 만들기
  - 학생 기록: 노래 도장, 투표, 바꾼 가사 제출 → 시트에 저장, 새로 고쳐도 남는지
  - 회원방: 자료방(링크 여러 개·QR), 운영진만 자료 가리기, 일정 달력, 공지,
            대화방·쪽지·'입력하고 있어요', 활동 후기(사진 3장·넘겨 보기·공감)
  - 운영진: 관리 화면, 계정 목록, 곡 고치기(공개 동의), 오늘의 동요 저장, 기록 내려받기
  - 체험 모드, 휴대폰 화면(옆으로 밀리지 않는지), 시안(preview) 페이지
  - 시험하는 동안 화면에 오류가 하나도 없었는지

  서버는 Collector.gs 를 흉내 서버(tests/mock)에서 그대로 돌리고, 구글 로그인과 실시간 대화는
  가짜로 바꿔 끼워요. 진짜 시트·진짜 회원 기록은 건드리지 않아요.
  화면 사진은 tests/결과/ 에 남아요(저장소에는 올라가지 않아요).

새 기능을 넣으면 tests/full_test.py 에 그 기능을 밟아 보는 시험도 한 가지 더해요.
